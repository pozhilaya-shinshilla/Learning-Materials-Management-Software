# Сервис управления учебными материалами — Backend (этап 1)

Реализация backend-логики согласно техническому заданию (раздел 4), на текущем этапе —
в виде самостоятельных Python-классов с CLI-интерфейсом, без поднятия HTTP-сервера и БД.
Архитектура подготовлена так, чтобы слой хранения можно было заменить на PostgreSQL +
SQLAlchemy, а CLI — на FastAPI-роуты, без изменения бизнес-логики (см. «Дальнейшие шаги»).

## Стек

- Python 3.12
- Менеджер пакетов и окружений: [uv](https://docs.astral.sh/uv/)
- Зависимости: `nltk` (морфология поиска) используется в коде уже сейчас; FastAPI, SQLAlchemy,
  Alembic, Pydantic зафиксированы для будущих этапов — см. `pyproject.toml` и `uv.lock`
- Линтер/форматтер: [ruff](https://docs.astral.sh/ruff/)

## Запуск

### 1. Требования

- Python 3.12 или новее — https://www.python.org/downloads/ (на Windows не забудьте
  поставить галку «Add python.exe to PATH» в установщике);
- менеджер пакетов **uv** (рекомендуется, но не обязателен — см. вариант без uv ниже).

Установка uv:

```bash
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# macOS/Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

После установки закройте и откройте терминал заново и проверьте: `uv --version`.

### 2. Получить код

```bash
git clone <ссылка на репозиторий>
cd sms
```

### 3. Установить зависимости и запустить

```bash
uv sync            # создаст .venv и установит fastapi/sqlalchemy/alembic/pydantic/nltk/ruff
                    # по версиям, зафиксированным в uv.lock
uv run -m src.main
```

Без установленных зависимостей приложение не запустится: `src/services/morphology.py` импортирует
`nltk` при старте. Если uv недоступен, а Python 3.12+ уже есть, создайте окружение вручную
(единственная сторонняя библиотека, которую код импортирует на текущем этапе, — `nltk`):

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install nltk
python -m src.main
```

### 4. Вход в систему

При запуске автоматически создаётся администратор. Пароля по умолчанию в коде нет:
логин, email и пароль берутся из переменных окружения `ADMIN_LOGIN`, `ADMIN_EMAIL`,
`ADMIN_PASSWORD` или из файла `.env` в корне проекта (шаблон — `.env.example`,
сам `.env` в git не попадает; переменные окружения важнее файла):

```bash
cp .env.example .env     # затем впишите свой ADMIN_PASSWORD (не короче 8 символов)
uv run -m src.main
```

Если `ADMIN_PASSWORD` не задан, при каждом запуске генерируется случайный пароль, который
выводится один раз в начале работы. Заданный пароль на экран не выводится. Логин по умолчанию —
`admin`, email — `admin@example.org`.

Залогинившись под администратором, вы попадаете в меню — дальше все действия (создание
пользователей, дисциплин, материалов и т.д.) выполняются через пункты меню. Полный список пунктов
по ролям — в разделе «Роли и возможности CLI» ниже.

## Поиск, фильтры и сортировка

- Поиск идёт по названию и описанию **с учётом морфологии русского и английского языков**
  (стеммеры Snowball из библиотеки NLTK, `src/services/morphology.py`): запрос «лекция» найдёт
  «лекции», «лекцией», «по лекциям», а `database` — `databases`;
  запрос из нескольких слов требует, чтобы нашлись все слова; допустим и ввод части слова.
- Фильтры: дисциплина, тема (по названию), формат файла, период по дате загрузки
  (`ДД.ММ.ГГГГ`, обе границы необязательны).
- Сортировка: по дате (новые/старые) и по названию (А–Я / Я–А).

## Восстановление пароля

На экране входа введите `/reset`: указывается email, на него приходит одноразовый код
(действует 30 минут, хранится только в виде хеша), по коду задаётся новый пароль. Ответ не
зависит от того, есть ли такой email в системе. На этом этапе письмо **имитируется** — выводится
в консоль строками `[ПОЧТА, имитация отправки]`; реальная отправка по SMTP подключается заменой
класса `EmailSender` в `bootstrap.py` без изменения сервисов.

## Загрузка и скачивание файлов

При создании материала (пункт «Добавить материал») указывается **локальный путь** к файлу на
диске — формат и размер определяются автоматически по расширению и содержимому файла, вводить
их вручную не нужно. Файл физически копируется в `data/uploads/` (папка создаётся сама, в
`.gitignore` уже добавлена). При скачивании материал копируется из хранилища в указанную папку
(по умолчанию — текущая).

## Валидация

Правила собраны в `src/domain/validation.py` и используются и сервисами, и CLI.

- вход: логин и пароль не пустые, логин соответствует формату
- логин: 3–32 символа, латиница/цифры/`_`/`-`, уникален
- email: формат `local@domain.tld`, уникален
- пароль: не короче 8 символов
- название материала/дисциплины/темы: не пустое; дисциплины уникальны, темы уникальны внутри дисциплины
- файл: существует, формат из списка допустимых, размер не больше 100 МБ

## Поведение интерфейса

- **Ошибка ввода не выбрасывает в меню.** Неверное значение объясняется, и тот же вопрос
  задаётся снова. Выйти из любого действия можно вводом `0` (или `отмена`).
- **Дисциплины и темы вводятся названием**, а не ID (регистр не важен). Перед вопросом
  выводится список доступных вариантов.
- **Пустые справочники сообщаются сразу**: нет материалов, дисциплин, тем, избранного или других
  пользователей — действие не начинается, выводится подсказка, что сделать.
- **Редактировать и удалять** можно только доступные материалы: преподаватель видит и выбирает
  только свои, администратор — все.
- После каждого действия — «Нажмите Enter», затем экран очищается и меню перерисовывается.

## Ролевая модель

Права накапливаются: у преподавателя есть все действия студента + свои, у администратора — все
действия преподавателя (а значит и студента) + управление пользователями и журналом событий.
Администратор не может заблокировать, удалить или сменить роль собственной учетной записи.

## Роли и возможности CLI

| Роль          | Возможности в меню                                                                 |
|---------------|--------------------------------------------------------------------------------------|
| Студент       | каталог, сведения о материале, поиск/фильтры/сортировка, скачивание, избранное      |
| Преподаватель | всё из прав студента + «Мои материалы», создание/редактирование/удаление своих материалов, создание и переименование дисциплин и тем |
| Администратор | всё из прав преподавателя (материалы — любые) + пользователи (создание/роль/блокировка/удаление), журнал событий |

Регистрация новых пользователей выполняется только администратором — согласно п. 4.1.6.6 ТЗ.
