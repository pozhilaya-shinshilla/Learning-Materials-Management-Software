# Сервис управления учебными материалами — Backend (этап 3: паттерны, Pydantic DTO, FastAPI)

Реализация backend-логики согласно техническому заданию (раздел 4), на текущем этапе —
в виде самостоятельных Python-классов с CLI-интерфейсом, без HTTP-сервера. Данные хранятся
в PostgreSQL (SQLAlchemy 2.x), схему создают миграции Alembic. Других хранилищ нет: сервисы и тесты работают
с PostgreSQL. CLI можно заменить на FastAPI-роуты без изменения бизнес-логики (см. «Дальнейшие шаги»).

## Стек

- Python 3.12
- Менеджер пакетов и окружений: [uv](https://docs.astral.sh/uv/)
- Зависимости: FastAPI + Uvicorn (REST API), Pydantic (DTO), SQLAlchemy + psycopg 3 + Alembic (БД);
  морфологию поиска выполняет PostgreSQL — см. `pyproject.toml` и `uv.lock`
- Линтер/форматтер: [ruff](https://docs.astral.sh/ruff/)

## Запуск

### 1. Требования

- Python 3.12 или новее — https://www.python.org/downloads/ (на Windows не забудьте
  поставить галку «Add python.exe to PATH» в установщике);
- менеджер пакетов **uv** (рекомендуется, но не обязателен — см. вариант без uv ниже).

Установка uv:

```bash
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# macOS/Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

После установки закройте и откройте терминал заново и проверьте: `uv --version`.

### 2. Получить код

```bash
git clone <ссылка на репозиторий>
cd sms
```

### 3. Установить зависимости, поднять БД и применить миграции

```bash
uv sync                          # .venv и зависимости по uv.lock
cp .env.example .env             # Windows: copy .env.example .env; задайте ADMIN_PASSWORD
docker compose up -d             # PostgreSQL 16 (базы lms и lms_test)
uv run alembic upgrade head      # создать таблицы (схему создаёт только Alembic)
uv run -m src.main               # запустить приложение
```

Без Docker подойдёт любой PostgreSQL 15+: создайте пользователя и базу и пропишите
`DATABASE_URL` в `.env` (по умолчанию `postgresql+psycopg://lms:lms@localhost:5432/lms`).
База должна иметь UTF-8 локаль (`C.UTF-8`, `en_US.UTF-8`, `ru_RU.UTF-8`): уникальность
названий и email без учёта регистра держится на `lower(...)`, а в локали `C` он не меняет
кириллицу. Приложение проверяет это при старте.

Если миграции не применены, приложение сообщит об этом и подскажет `alembic upgrade head`.

**Веб-интерфейс.** В `docker compose up -d --build` его собирает и раздаёт отдельный контейнер `web` (nginx): `http://localhost:8000/`, запросы `/api` он проксирует в контейнер приложения. Без Docker интерфейс запускается из папки `frontend` (`npm ci`, затем `npm run dev` или `npm run build && npm run preview`). Подробности — в [frontend.md](frontend.md).

### 4. База данных и миграции

ER-диаграмма и ограничения: [`docs/er.md`](er.md). Модели: `src/database/models.py`.

История команд, которыми создавалась схема:

```bash
uv add "alembic[tz]" "psycopg[binary]"                 # зависимости
uv run alembic init migrations                          # каталог migrations/ и alembic.ini
# настроены migrations/env.py (metadata моделей, URL из settings) и alembic.ini
uv run alembic revision --autogenerate -m "create lms schema"   # создать миграцию по моделям
# миграция проверена вручную, в downgrade добавлено удаление enum-типов
uv run alembic upgrade head                             # применить
uv run alembic current                                  # текущая ревизия -> (head)
uv run alembic history                                  # список ревизий
uv run alembic check                                    # модели и схема не расходятся
uv run alembic downgrade -1                             # откат; затем снова upgrade head
```

Новая миграция после изменения моделей: `uv run alembic revision --autogenerate -m "add ..."`,
прочитать файл в `migrations/versions/`, применить `uv run alembic upgrade head`.
Применённые миграции не редактируются: исправления идут новой ревизией.
Сброс учебной базы с нуля: `docker compose down -v`, затем `docker compose up -d` и `alembic upgrade head`.

### 5. Тесты

```bash
docker compose up -d             # тестовой базе нужен PostgreSQL (база lms_test создаётся сама)
uv run pytest
```

Все тесты, кроме чистой логики (валидаторы, сортировка), работают с PostgreSQL: база берётся из
`TEST_DATABASE_URL` (по умолчанию `lms_test` из `docker-compose.yaml`) и пересоздаётся через Alembic.
Каждый тест идёт в одной сессии, которая откатывается в конце. Если сервер недоступен, тесты
**падают** с понятным сообщением, а не пропускаются. Тестовая база не должна совпадать с `DATABASE_URL`.

### 6. Установка без uv

Если uv недоступен, а Python 3.12+ уже есть, создайте окружение вручную:

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install "alembic[tz]" fastapi "psycopg[binary]" pydantic python-multipart sqlalchemy uvicorn
python -m src.main
```

### 4. Вход в систему

При запуске автоматически создаётся администратор. Пароля по умолчанию в коде нет:
логин, email и пароль берутся из переменных окружения `ADMIN_LOGIN`, `ADMIN_EMAIL`,
`ADMIN_PASSWORD` или из файла `.env` в корне проекта (шаблон — `.env.example`,
сам `.env` в git не попадает; переменные окружения важнее файла):

```bash
cp .env.example .env     # затем впишите свой ADMIN_PASSWORD (не короче 8 символов, с заглавной буквой, цифрой и специальным символом)
uv run -m src.main
```

`ADMIN_PASSWORD` обязателен: если он не задан, программа сообщает об этом и завершается.
Заданный пароль на экран не выводится. Логин по умолчанию — `admin`, email —
`admin@example.org`.

Залогинившись под администратором, вы попадаете в меню — дальше все действия (создание
пользователей, дисциплин, материалов и т.д.) выполняются через пункты меню. Полный список пунктов
по ролям — в разделе «Роли и возможности CLI» ниже.

## Запуск «включил и забыл»

Один вход в приложение — `src/main.py`. Команда по умолчанию поднимает REST API: приложение само
дожидается базы данных, применяет миграции (`alembic upgrade head`) и начинает принимать запросы.

**Всё в Docker (рекомендуется):**

```bash
cp .env.example .env              # впишите ADMIN_PASSWORD
docker compose up -d --build      # PostgreSQL + API + веб-интерфейс (nginx) на http://localhost:8000
docker compose logs -f app        # журнал приложения
```

Контейнер приложения стартует после того, как БД стала готова, перезапускается сам
(`restart: unless-stopped`), а загруженные файлы лежат в томе `lms_uploads` и не пропадают при
пересоздании контейнера. Нужен Docker Compose 2.24+ (необязательный `env_file`).

**Без Docker для приложения (БД в Docker или своя):**

```bash
docker compose up -d db           # только PostgreSQL
uv run python -m src.main         # ждёт БД, применяет миграции, запускает сервер
```

| Команда | Что делает |
|---|---|
| `uv run python -m src.main` | запустить REST API (то же, что `serve`) |
| `uv run python -m src.main serve --host 0.0.0.0 --port 9000` | задать адрес и порт; `--no-migrate` не применять миграции |
| `uv run python -m src.main cli` | консольное приложение, те же сервисы и та же БД |
| `uv run python -m src.main migrate` | только применить миграции и выйти |

Настройки запуска (необязательные): `APP_HOST` (по умолчанию `127.0.0.1`), `APP_PORT` (`8000`),
`DB_WAIT_SECONDS` (`30`), `AUTO_MIGRATE` (`1`), `APP_TIMEZONE` (`Europe/Volgograd`) — см. `.env.example`.
Ошибки настроек (нет `ADMIN_PASSWORD`, неверный порт, БД не ответила) выводятся одной понятной
строкой до запуска, а не трассировкой.

Swagger UI: `http://localhost:8000/docs`. Вход: `POST /api/auth/login`, затем кнопка **Authorize**
и токен. Список методов, права по ролям и формат ошибок — в [api.md](api.md).

## Поиск, фильтры и сортировка

- Поиск полнотекстовый и выполняется в PostgreSQL одним запросом (GIN-индекс
  `ix_materials_search_vector`, конфигурация `russian`): учитывается морфология русского и английского
  языков, поэтому запрос «лекция» найдёт «лекции», «лекцией», «по лекциям», а `database` — `databases`.
  Запрос из нескольких слов требует, чтобы нашлись все слова; допустим и ввод начала слова («диффер»);
  стоп-слова («и», «по») игнорируются, регистр и «ё» не важны.
- Фильтры: дисциплина, тема (по названию), формат файла, период по дате загрузки
  (`ДД.ММ.ГГГГ`, обе границы необязательны). Сутки считаются в часовом поясе приложения
  `APP_TIMEZONE` (по умолчанию `Europe/Volgograd`), а не сервера.
- Сортировка выполняется базой данных (`ORDER BY`): по дате (новые/старые) и по названию (А–Я / Я–А);
  равные значения идут в порядке добавления.

## Восстановление пароля

На экране входа введите `/reset`: указывается email, на него приходит одноразовый код
(действует 30 минут, хранится только в виде хеша), по коду задаётся новый пароль. Ответ не
зависит от того, есть ли такой email в системе. На этом этапе письмо **имитируется** — выводится
в консоль строками `[ПОЧТА, имитация отправки]`; реальная отправка по SMTP подключается заменой
класса `EmailSender` в `bootstrap.py` без изменения сервисов.

## Загрузка и скачивание файлов

При создании материала (пункт «Добавить материал») указывается **локальный путь** к файлу на
диске — формат и размер определяются автоматически по расширению и содержимому файла, вводить
их вручную не нужно. Файл физически копируется в `data/uploads/` (папка создаётся сама, в
`.gitignore` уже добавлена). При скачивании материал копируется из хранилища в указанную папку
(по умолчанию — текущая).

## Валидация

Правила собраны в `src/domain/validation.py` и используются и сервисами, и CLI.

- вход: логин и пароль не пустые, логин соответствует формату
- логин: 3–32 символа, латиница/цифры/`_`/`-`, уникален
- email: формат `local@domain.tld`, уникален
- пароль: не короче 8 символов, хотя бы одна заглавная буква, одна цифра и один специальный символ
  (любой, кроме букв, цифр и пробелов)
- название материала/дисциплины/темы: не пустое; дисциплины уникальны, темы уникальны внутри дисциплины
- файл: существует, формат из списка допустимых, размер не больше 100 МБ

## Поведение интерфейса

- **Ошибка ввода не выбрасывает в меню.** Неверное значение объясняется, и тот же вопрос
  задаётся снова. Выйти из любого действия можно вводом `0` (или `отмена`).
- **Дисциплины и темы вводятся названием**, а не ID (регистр не важен). Перед вопросом
  выводится список доступных вариантов.
- **Пустые справочники сообщаются сразу**: нет материалов, дисциплин, тем, избранного или других
  пользователей — действие не начинается, выводится подсказка, что сделать.
- **Редактировать и удалять** можно только доступные материалы: преподаватель видит и выбирает
  только свои, администратор — все.
- После каждого действия — «Нажмите Enter», затем экран очищается и меню перерисовывается.

## Ролевая модель

Права накапливаются: у преподавателя есть все действия студента + свои, у администратора — все
действия преподавателя (а значит и студента) + управление пользователями и журналом событий.
Администратор не может заблокировать, удалить или сменить роль собственной учетной записи.

## Роли и возможности CLI

| Роль          | Возможности в меню                                                                 |
|---------------|--------------------------------------------------------------------------------------|
| Студент       | каталог, сведения о материале, поиск/фильтры/сортировка, скачивание, избранное      |
| Преподаватель | всё из прав студента + «Мои материалы», создание/редактирование/удаление своих материалов, создание и переименование дисциплин и тем |
| Администратор | всё из прав преподавателя (материалы — любые) + пользователи (создание/роль/блокировка/удаление), журнал событий |
